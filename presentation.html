  • query_stock_data：執行 DuckDB SQL 查詢本地量化庫。
    SELECT symbol, name, close, volume
    FROM close_price

  • get_stock_schema：動態查詢 6 大資料表欄位定義與最新交易日。
  • web_search：聯網調用 SearXNG 即時檢索新聞與事件背景。
自律代理執行流程 (Agent Execution Loop) Server-Side Loop
  1. 請求攔截：接收客戶端請求，自動將台股資料庫現況與工具清單注入 System Prompt。
  2. 模型決策：Qwen 3.8 評估問題，產生結構化 tool_calls（包含 SQL 語法與調用原因）。
  3. 本地秒級執行：Gateway 執行 DuckDB 查詢（限制最多 100 筆與唯讀安全防護），並動態補齊券商中文分點名稱。
  4. 遞迴反饋：將 role: tool 結果封裝，再次請求模型進行綜合量化解讀。
  5. 串流輸出：將模型產出的最終量化報告以 SSE 流式格式傳回給前端（Cline / Chat UI）。

Root Cause Analysis & Fixes

關鍵問題排查：Cline Socket 中斷錯誤根治

深入剖析 SocketError: other side closed (UND_ERR_SOCKET) 協議成因與代碼級修復方案。

根本成因剖析 (Root Cause) Protocol Conflict
  • 客戶端環境：Cline (VS Code 擴充套件) 內部採用 Node.js 的 undici 作為 HTTP Client。
  • HTTP/1.1 串流協定衝突： Gateway 原先發送 SSE 時帶有 Connection: keep-alive 標頭，但未傳送 Content-Length 亦未使用 chunked 分塊編碼。
  • EOF 界定失敗： HTTP/1.1 規定無長度標頭的流必須透過 Server 主動關閉連線（FIN）界定結尾。Gateway 承諾了 keep-alive 卻未主動結束 Socket，導致 undici 在收到 data: [DONE] 後判定連線異常中斷。
  • 營收資料重複： 原通配符 api_revenue_*.parquet 同時匹配到切檔與全量庫，造成 2026-09 查詢出現雙倍重複。
修復成果與實測驗證 (Resolution) Production Ready
  • 標頭修正：將 SSE 標頭全面改為 Connection: close，與 TensorFold 核心統一。
  • 連線標記：在 data: [DONE] 輸出後明確設定 self.close_connection = True，發送標準 TCP FIN。
  • 異常保護：Socket 寫入包覆 BrokenPipeError 與 ConnectionResetError 容錯。
  • 營收防重：改為精確切檔通配符 api_revenue_????-??.parquet，徹底消除重複。
  • 9 月營收驗證：確認 16 家提早申報公司（毅嘉、德律、金麗科等）檔案無損健康。
